04. RAID Architectures & Reliability

In 1988, David Patterson, Garth Gibson, and Randy Katz published their foundational paper at UC Berkeley: "A Case for Redundant Arrays of Inexpensive Disks (RAID)". The paper established a methodology for addressing a growing performance and reliability chasm in computer architecture: CPUs were doubling in speed every 18 months, while magnetic disk access times improved by only a few percent per year.

RAID organizes multiple physical storage disks into an integrated logical array, coordinated by hardware or operating system drivers along three design axes: Capacity, Performance, and Reliability.

1. The Three Orthogonal Design Axes & Striping

When aggregating N identical physical disks of capacity C into an array:

  • Capacity Efficiency: The fraction of raw disk storage usable for user data after reserving space for mirroring or parity blocks.
  • Performance Multiplier: How many concurrent operations the array can service simultaneously. High-throughput workloads benefit from parallel read/write data transfers across multiple spindles.
  • Reliability & Fault Tolerance: How many physical drive failures the array can survive without permanent data loss.

Striping Fundamentals: Chunk Size Trade-offs

Data Striping partitions a contiguous stream of logical data into discrete chunks and writes successive chunks across different disks in round-robin sequence:

Chunk Size (Stripe Depth) Trade-off:
  • Fine-Grained Striping (Byte or Word Level): Every I/O request accesses all disks concurrently. Delivers high transfer rates for large sequential transfers, but prevents the array from servicing multiple independent I/O requests concurrently (all disks seek in unison).
  • Coarse-Grained Striping (Block Level, e.g. 64 KB – 256 KB): Small I/O requests fit entirely inside a single disk chunk. Multiple independent read requests can be serviced in parallel by different disks, yielding maximum IOPS (I/O Operations Per Second) for multi-threaded databases and web servers.

2. Taxonomy of Standard RAID Levels

Figure 4.1: Structural Topology of Standard RAID Levels
Block allocation mapping showing striping, mirroring, dedicated parity, and distributed rotating parity.

1. RAID 0: Non-Redundant Striping

  • Data Layout: Pure block-level striping without parity or mirroring. Block 0 → Disk 0, Block 1 → Disk 1, Block 2 → Disk 0, etc.
  • Capacity: N × C (100\% efficiency).
  • Performance: N × sequential read and write throughput.
  • The Reliability Disaster: If any single physical disk suffers hardware failure, all data in the array is permanently destroyed. Because disk failures are independent Poisson processes, the Mean Time To Failure (MTTF) of a RAID 0 array drops precipitously: 
    MTTFRAID 0 = MTTFsingle disk / N
    An array of 10 disks with an individual MTTF of 1,000,000 hours will experience an array failure every 100,000 hours (11.4 years).

2. RAID 1: Mirroring / Shadowing

  • Data Layout: Every logical block is written identically to two (or more) separate physical disks.
  • Capacity: C (50\% capacity efficiency for 2-way mirrors). Highly expensive per gigabyte.
  • Performance: Write throughput equals a single disk (since both disks must be updated). Read throughput reaches 2 ×, as the controller can schedule reads across both spindles in parallel.
  • Reliability: Survives the physical death of any one disk. If a disk fails, the remaining disk continues servicing I/O with zero performance penalty.

3. RAID 4: Block Striping with Dedicated Parity Disk

RAID 4 attempts to balance storage efficiency and fault tolerance by striping data blocks across N - 1 data disks, while writing computed parity blocks to a single dedicated parity disk.

The Small-Write Parity Disk Bottleneck in RAID 4:
Suppose an application updates a single 4 KB data block (D1 → D1'). In order to update the corresponding parity block (P → P'), the controller must calculate: 
P' = (D1 (old) ⊕ D1 (new)) ⊕ P(old)
This creates the notorious Read-Modify-Write Penalty:
  1. Read old data block D1.
  2. Read old parity block P.
  3. Compute new parity: P' = D1 ⊕ D1' ⊕ P.
  4. Write new data block D1'.
  5. Write new parity block P'.
A single-block write requires 2 physical disk reads and 2 physical disk writes (4 total I/O operations). Because every write in the entire system must update the dedicated parity disk, the parity disk arm thrashes continuously, capping system write throughput at the speed of one disk!

4. RAID 5: Distributed Rotating Parity

RAID 5 permanently eliminates the RAID 4 write bottleneck by rotating the parity blocks round-robin across all physical disks.

  • Stripe 0 stores parity on Disk 3 (Ap).
  • Stripe 1 stores parity on Disk 2 (Bp).
  • Stripe 2 stores parity on Disk 1 (Cp).
  • Stripe 3 stores parity on Disk 0 (Dp).

Because parity updates are distributed uniformly across all spindles, multiple independent write operations can execute in parallel. RAID 5 yields a usable capacity of (N - 1) × C, tolerates the loss of exactly one disk, and remains the historical enterprise workhorse.

5. RAID 6: Dual Distributed Parity (P + Q)

RAID 6 extends RAID 5 by computing two independent parity blocks per stripe (P and Q), distributing both across the array:

  • Parity P: The standard linear XOR parity (P = D0 ⊕ D1 ⊕ D2).
  • Parity Q: A non-linear Reed-Solomon polynomial code computed over a Galois Field GF(28) or diagonal dual-XOR matrix.
  • Capacity: (N - 2) × C.
  • Fault Tolerance: Survives two simultaneous physical disk failures without data loss.

6. Nested RAID: RAID 10 (1+0) vs. RAID 01 (0+1)

Enterprise databases frequently deploy hybrid arrays combining the throughput of striping with the resilience of mirroring:

RAID 10 (Stripe of Mirrors) — PREFERRED

Disks are mirrored in pairs (Disk 0/1, Disk 2/3), and data is striped across the mirrors.

Failure Resilience: If Disk 0 fails, the array only loses data if its specific mirror (Disk 1) also fails. It can survive a secondary failure of Disk 2 or Disk 3! Probability of surviving a 2nd failure is N-2⁄N-1 ≈ 67\%--80\%.

RAID 01 (Mirror of Stripes) — FRAGILE

Data is striped across two sets of disks, and the two stripes are mirrored.

Failure Hazard: If Disk 0 fails, the entire Stripe A becomes inoperative. The array is reduced to a single surviving stripe (Stripe B). Any subsequent failure of any disk in Stripe B destroys the entire array!

3. Mathematical Foundations: XOR Parity & The URE Rebuild Crisis

Boolean XOR Reconstruction Mechanics

The mathematical property that makes parity reconstruction computationally efficient is the self-inverting nature of the exclusive-OR (⊕) operator:

The Parity Invariant: 
D0 ⊕ D1 ⊕ D2 = P
D0 ⊕ D1 ⊕ D2 ⊕ P = 0
If Disk 1 physically dies, the missing data D1 is reconstructed by reading the surviving data blocks and parity, and XORing them together: 
D1 = D0 ⊕ D2 ⊕ P

The Modern URE Crisis: Why RAID 5 is Dead for Large Disks

In modern storage engineering, RAID 5 is considered unfit for multi-terabyte mechanical drives due to a physical error phenomenon known as the Unrecoverable Read Error (URE):

  • Consumer and enterprise SATA hard drives specify a non-recoverable read error rate of approximately 1 sector error in every 1014 bits read (roughly 1 sector error per 12.5 Terabytes).
  • When a drive dies in an 8-disk RAID 5 array of 12 TB drives, the controller must read 84 Terabytes of raw data from the surviving disks to rebuild the missing drive.
  • At 1014 bits per error, the mathematical probability of reading 84 TB without encountering a single URE is less than 1%!
The RAID 5 Rebuild Trap: When a URE occurs on a surviving disk during a RAID 5 rebuild, the parity equation cannot be solved. The rebuild aborts, the array collapses, and all data across all disks is permanently lost. This physical reality forces all modern large-capacity arrays to utilize RAID 6 or RAID 10.

4. Software RAID vs. Hardware RAID & Modern Filesystems

1. Hardware RAID Controllers

A dedicated PCIe expansion card with on-board XOR acceleration chips and Battery-Backed Write Cache (BBWC).

The Write-Hole Defense: If system power cuts out mid-write, the controller retains unwritten parity in NVRAM and flushes it upon reboot, preventing the array parity from becoming corrupt.

2. Software RAID & Modern CoW (ZFS)

Managed directly by OS kernel drivers (Linux mdadm) or integrated into Copy-on-Write filesystems (ZFS RAID-Z / Btrfs).

Eliminating the Write Hole: ZFS never overwrites data in place; new blocks and dynamic parity are written to fresh unallocated sectors transactionally, rendering write-hole corruption architecturally impossible.
