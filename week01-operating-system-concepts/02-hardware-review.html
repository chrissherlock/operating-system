02. Computer Hardware Review

Tanenbaum Chapter 1.3: Processors, Memory Hierarchy, Disks, I/O Devices, Buses, and Booting.

1. Processors (CPUs) & Execution Mechanics

The Central Processing Unit (CPU) is the computational brain of the computer, executing instructions fetched from main memory. The CPU follows the classical fetch-decode-execute cycle:

  • Fetch: Retrieve the instruction at the memory address currently designated by the Program Counter (PC).
  • Decode: Interpret the operation code (opcode) to determine the instruction type and identify the required operands.
  • Execute: Carry out the operation within the Arithmetic Logic Unit (ALU), manipulate data registers, and adjust processor state flags.

Key Processor Registers

CPUs contain internal high-speed storage registers that operate at core clock speeds with zero wait states:

  • General-Purpose Registers: Hold local variables, arithmetic operands, and temporary intermediate results.
  • Program Counter (PC): Stores the memory address of the next machine instruction to be fetched.
  • Stack Pointer (SP): Points to the top of the current call stack frame in memory, tracking local variables, parameters, and return addresses.
  • Program Status Word (PSW): Contains condition code bits (carry, overflow, zero, sign), CPU priority level, mode bits (user vs. kernel mode), and interrupt enablement flags.

Pipelining, Superscalar, & Multicore Architectures

Modern processors maximize instruction throughput through concurrency:

  • Pipelining: Deconstructs instruction processing into sequential stages (e.g., Fetch, Decode, Execute, Writeback), allowing an instruction to be decoded while the previous one is executed and the next one is fetched.
  • Superscalar Execution: Features multiple parallel execution units (multiple ALUs, floating-point units). If consecutive instructions are independent, both are issued and executed simultaneously.
  • Multithreading & Hyperthreading: Duplicates architectural state (registers, PC, PSW) on a single physical core, allowing near-instantaneous thread context switching when one thread stalls on memory access.
  • Multicore Processors: Embed multiple complete, independent CPU cores onto a single silicon die, each with dedicated L1/L2 caches and shared L3 caches.

Hardware Glossary: Beginner Guide to Silicon Mechanics
What does "Latched" mean?

Captured and locked in place. Voltages on memory buses drift and fluctuate. When the register clock triggers, storage circuits (flip-flops) snap shut like a camera shutter, freezing those electrical 1s and 0s rock-solid so downstream stages read an unchanging value.

What is the "Rising Clock Edge"?

The CPU clock is a square wave oscillating between 0V (low) and ~1V (high). The rising edge is the exact instantaneous transition when voltage jumps from 0 to 1. Like a conductor's baton downbeat, this single moment tells all registers across the chip to advance together.

What is a "Pipeline Bubble"?

An idle cycle where a stage does no useful work—an enforced NOP (No Operation). Just like empty wash bays when an automated car wash first starts up, downstream stages sit idle until the first real instruction shifts into them.

2. Privilege Modes & Hardware Protection

To prevent rogue or faulty user software from crashing the operating system or corrupting other programs, CPU hardware enforces distinct privilege execution levels:

  • Kernel Mode (Supervisor Mode): Complete, unrestricted access to the entire physical address space, all machine instructions (including direct device I/O, MMU modifications, and timer interrupts), and system configuration tables. The operating system kernel runs exclusively in kernel mode.
  • User Mode: A restricted subset of instructions is available. Direct memory access to kernel space, modification of control registers, and raw I/O instructions are strictly prohibited and trap to the OS kernel.
The TRAP Instruction & System Calls

When an application requires operating system services (such as reading a file from disk), it executes a specialized TRAP instruction (or syscall / sysenter). This hardware instruction switches the CPU from user mode to kernel mode and branches unconditionally to a predefined vector in the kernel's Interrupt Descriptor Table (IDT), allowing controlled privileged execution.

Deep Dive: What is MSR_LSTAR? (Fast System Call Dispatch)

MSR_LSTAR stands for Model-Specific Register: Long System Target Address Register (x86 MSR address 0xC0000082). It is a dedicated on-die 64-bit CPU register that holds the kernel's direct system call entry vector.

The Legacy Way: INT 0x80 (Slow)

In 32-bit x86, traps were software interrupts. The CPU had to pause execution, read the Interrupt Descriptor Table (IDT) in DRAM, perform permission checks, read the Task State Segment, and push flags to the stack—wasting dozens of clock cycles on memory reads before reaching kernel code.

The Modern 64-bit Way: MSR_LSTAR (Fast)

During boot, the OS kernel writes its entry point into MSR_LSTAR via the privileged wrmsr instruction (entry_SYSCALL_64 on Linux, KiSystemCall64 on Windows). When a program executes syscall, the CPU bypasses the IDT entirely and jumps directly to MSR_LSTAR in silicon.

The Atomic Hardware Microcode Sequence:

When an application executes the syscall instruction, the CPU executes an atomic microcode routine:

  1. Saves Program Counter: Copies current RIP into register RCX (saving where to return).
  2. Saves CPU Flags: Copies RFLAGS into register R11.
  3. Elevates Privilege: Flips the internal processor Mode Bit from Ring 3 (User) to Ring 0 (Kernel).
  4. Masks Flags: Clears unsafe flag bits specified in MSR_FMASK (disabling hardware interrupts while entering).
  5. Instant Vector Jump: Loads RIP = MSR_LSTAR with zero memory lookups. The kernel starts running immediately.

3. Virtual Memory & The Memory Management Unit (MMU)

Early operating systems allocated physical memory contiguously. If an application requested 64 KiB, the operating system had to locate 64 KiB of uninterrupted physical RAM. This model suffered from severe memory fragmentation, made it impossible to run programs larger than physical memory, and provided zero memory safety: a rogue pointer could write directly into the operating system kernel or neighboring application memory.

Modern architectures decouple the addresses generated by programs from the physical addresses wired into silicon using Virtual Memory, managed directly by specialized hardware called the Memory Management Unit (MMU).

Virtual vs. Physical Address Spaces

Every user-mode application executes within its own private, isolated virtual address space. To the program, it appears as though it owns a massive, continuous block of memory (e.g., 4 GiB on 32-bit systems or 256 TiB in standard 48-bit x86-64 user space). The physical memory chips (DRAM), by contrast, are partitioned into fixed-size physical blocks called page frames (typically 4 KiB in size).

Address Translation Mechanics

A virtual memory address generated by the CPU is divided cleanly into two logical components:

  • Virtual Page Number (VPN): The upper address bits, which identify which page in the address space is being accessed.
  • Page Offset: The lower address bits, which specify the exact byte location within that 4 KiB page. Because 212 = 4096, standard 4 KiB pages use the lowest 12 bits as the offset.

The hardware MMU takes the Virtual Page Number and indexes into the active process's Page Table to discover the corresponding Physical Frame Number (PFN). The lowest 12 bits of the original address (the offset) pass through completely unmodified, because the byte offset within a virtual page is identical to the byte offset within a physical frame:

Hierarchical Multi-Level Page Tables

If an operating system maintained a flat single-level table of 4 KiB pages across a 64-bit address space, the page table alone would require billions of gigabytes of RAM per process. Operating systems solve this by structuring page tables hierarchically as a multi-level tree (e.g., 4-level paging on x86-64 using PML4, PDPT, PD, and PT).

The CPU maintains a dedicated control register—CR3 on x86-64 or TTBR0/TTBR1 on ARM64—which holds the physical address of the root page table for the currently running process. If a range of virtual memory is unallocated, the entire subtree can be omitted, saving enormous amounts of physical RAM.

The Translation Lookaside Buffer (TLB)

Walking a 4-level page table requires up to 4 separate memory access cycles just to translate a single virtual address into a physical address before the actual data can be retrieved. To prevent memory access from slowing down by a factor of 5, the CPU features an on-die associative hardware cache called the Translation Lookaside Buffer (TLB).

  • TLB Hit: The MMU checks the TLB in a single clock cycle. If the VPN is present, the physical frame is retrieved immediately, bypassing all page tables. Modern hit rates typically exceed 98%.
  • TLB Miss: The MMU hardware walks the multi-level page table in physical memory, loads the translation into the TLB, and completes the access.
  • Context Switches & Flushes: Because each process maintains its own address space, reloading the root page table pointer (CR3) historically invalidated the entire TLB. Modern processors avoid this overhead using Address Space Identifiers (ASIDs) or Process-Context Identifiers (PCIDs), tagging TLB entries with process IDs so cache lines persist across context switches.

Page Faults & Demand Paging

Page table entries contain metadata status flags alongside the physical frame address:

  • Present Bit (P): 1 if the page resides in physical RAM; 0 if the page is unallocated or swapped out to storage.
  • Read/Write (R/W): Enforces read-only memory (e.g., executable code segments) vs. writable regions (heap/stack).
  • User/Supervisor (U/S): Prevents Ring 3 user programs from accessing kernel pages.
  • No-Execute (NX / XD): Prohibits executing instructions from data memory, mitigating buffer overflow attacks.

When an application attempts to access a page whose Present Bit is 0, the MMU halts execution and triggers a Page Fault exception (Interrupt 14 on x86). The CPU saves execution registers and vectors into the kernel page fault handler:

  1. The kernel reads the faulting virtual address from processor register CR2.
  2. The kernel checks its internal memory maps: if the address is truly invalid, it sends a SIGSEGV (Segmentation Fault) or STATUS_ACCESS_VIOLATION.
  3. If the page is valid but swapped out (demand paging), the kernel allocates a free physical RAM frame, initiates a disk read from swap/backing storage, updates the page table entry with the new PFN, and sets the Present bit to 1.
  4. The kernel executes an exception return (IRET), prompting the CPU to re-execute the exact instruction that previously faulted—this time succeeding with a seamless TLB hit.

4. Disks, I/O Devices, & Controller Hardware

I/O devices generally consist of two distinct parts: a physical component (the mechanical drive, screen, or cable) and an electronic component called the device controller.

  • Device Controllers: The electronic chip or circuit board that accepts commands from the OS and manages low-level electrical signals to the physical peripheral.
  • Memory-Mapped I/O & I/O Ports: The operating system communicates with device controllers by writing to and reading from designated controller registers mapped into memory addresses or separate I/O port spaces.

Three Fundamental I/O Approaches

  • Programmed I/O (Busy Waiting): The CPU polls the device controller in a tight loop until the requested operation completes, wasting CPU cycles.
  • Interrupt-Driven I/O: The CPU starts the transfer, moves on to execute other work, and receives a hardware interrupt signal from the controller when the transfer completes.
  • Direct Memory Access (DMA): A dedicated DMA controller chip orchestrates the bulk transfer of data directly between peripheral controllers and main memory without continuous CPU intervention, interrupting the processor only after an entire data block has been transferred.

5. Buses & The Boot Process

Modern computers utilize a hierarchy of specialized buses (PCIe, DMI, USB, DDR memory channels) connecting processors, memory, and controllers. Fast buses connect the CPU to high-speed caches and RAM, while secondary buses link standard peripherals.

How the Computer Boots Up

  1. When power is supplied, the CPU initializes its registers and executes boot firmware stored in non-volatile ROM/flash (the BIOS or modern UEFI).
  2. The firmware checks physical RAM, scans buses, and detects attached peripheral devices (Power-On Self-Test / POST).
  3. The firmware identifies the designated boot device and reads the first sector (Master Boot Record) or loads the EFI bootloader binary from the EFI System Partition (ESP).
  4. The bootloader (such as GRUB) copies the operating system kernel and initial RAM filesystem into main memory.
  5. The bootloader transfers execution to the kernel entry point. The OS kernel initializes hardware drivers, activates protected virtual memory, and spawns the initial user-space environment (such as init or systemd).
