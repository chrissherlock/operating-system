Deadlock Characterization & Coffman Conditions

Examine the formal mathematical conditions that define system deadlock. Analyze the Four Coffman Conditions, trace Resource Allocation Graphs (RAGs), and evaluate cycle detection algorithms in single-resource and multi-resource topologies.

1. Formal Definition of System Deadlock

A deadlock is defined formally in operating systems theory as a permanent state where a set of processes or threads is blocked because each process is holding a resource and waiting for another resource that is being held by some other process in the set.

Unlike busy-waiting loops or CPU starvation, a deadlocked thread consumes zero CPU cycles. It rests permanently in a sleep or blocked state (e.g., TASK_UNINTERRUPTIBLE in Linux or waiting on a kernel dispatcher object in Windows) until external administrative intervention or a watchdog timer destroys the process.

2. The Four Coffman Conditions

In 1971, Edward G. Coffman Jr., Michael J. Elphick, and Arie Shoshani established the foundational theorem proving that a system can enter a deadlocked state if and only if all four of the following conditions occur simultaneously:

  1. Mutual Exclusion: At least one resource must be held in a non-shareable mode. Only one process can use the resource at any given time. If another process requests that resource, the requesting process must be delayed until the resource is released.
  2. Hold and Wait: A process must be simultaneously holding at least one resource while actively waiting to acquire additional resources that are currently being held by other processes.
  3. No Preemption: Resources cannot be forcibly expropriated from a process. A resource can only be released voluntarily by the process holding it after that process has completed its task.
  4. Circular Wait: A closed chain of processes $\{P_0, P_1, \dots, P_n\}$ must exist such that $P_0$ is waiting for a resource held by $P_1$, $P_1$ is waiting for $P_2$, and $P_n$ is waiting for $P_0$.
The Necessary vs. Sufficient Distinction:
The Coffman conditions are necessary for deadlock (every deadlock exhibits all four), but depending on resource multiplicity, circular wait is only sometimes sufficient. In systems with multiple identical units per resource type, a cycle in the resource allocation graph is a necessary condition for deadlock, but not always sufficient.

3. Resource Allocation Graphs (RAGs) & Cycle Detection

Operating systems analyze deadlock topological states using directed graphs known as Resource Allocation Graphs (RAGs):

  • Process Nodes ($P_i$): Represented as circles.
  • Resource Nodes ($R_j$): Represented as rectangles (containing dots indicating available multi-unit instances).
  • Request Edge ($P_i \to R_j$): A directed edge from process $P_i$ to resource type $R_j$, indicating that $P_i$ is currently blocked waiting for an instance of $R_j$.
  • Assignment Edge ($R_j \to P_i$): A directed edge from resource instance $R_j$ to process $P_i$, indicating that an instance of $R_j$ has been allocated to $P_i$.
/* Graph Reduction Algorithm for Deadlock Detection */
bool detect_deadlock(rag_graph_t *g) {
    bool marked[MAX_PROCESSES] = { false };
    int work[MAX_RESOURCES];
    memcpy(work, g->available, sizeof(work));

    /* Find an unmarked process whose requests can be satisfied */
    bool progress = true;
    while (progress) {
        progress = false;
        for (int i = 0; i < g->num_processes; i++) {
            if (!marked[i] && can_satisfy_request(i, work, g)) {
                /* Simulate process completion: reclaim held resources */
                for (int j = 0; j < g->num_resources; j++) {
                    work[j] += g->allocation[i][j];
                }
                marked[i] = true;
                progress = true;
            }
        }
    }
    for (int i = 0; i < g->num_processes; i++) {
        if (!marked[i]) return true;
    }
    return false;
}
