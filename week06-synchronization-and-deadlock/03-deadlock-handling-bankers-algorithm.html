Deadlock Handling Strategies & The Banker's Algorithm

Explore the four foundational operating system strategies for managing deadlock. Contrast the Ostrich algorithm with static prevention, dynamic detection and recovery, and Dijkstra's Banker's Algorithm for resource allocation avoidance.

1. The Four Strategic Deadlock Regimes

Operating systems address the threat of deadlock through four primary architectural philosophies, balancing runtime overhead against catastrophic failure risk:

  • 1. The Ostrich Algorithm (Ignorance): Pretend that deadlocks never occur. If deadlocks happen only once a year, the performance cost of continuous prevention, detection, or avoidance outweighs the cost of occasional manual reboots or process termination. (Used by Linux, macOS, and Windows for general user-space applications).
  • 2. Deadlock Prevention: Ensure that the system never enters deadlock by structurally violating at least one of the four Coffman conditions beforehand.
  • 3. Deadlock Detection & Recovery: Allow the system to enter deadlock freely. Periodically run background graph-reduction algorithms to detect cycles, then recover by aborting processes or rolling back transactions.
  • 4. Deadlock Avoidance (The Banker's Algorithm): Require processes to declare their maximum resource needs in advance. Dynamically evaluate every resource request to ensure the system never departs a Safe State.

2. Deadlock Prevention: Violating Coffman Conditions

Deadlock prevention designs static architectural rules that guarantee at least one Coffman condition can never hold true:

  • Violating Mutual Exclusion: Make resources shareable. For example, using spooling for printers so multiple processes write concurrently to disk buffers rather than seizing the printer device directly. (Limitation: Fundamental hardware resources like mutexes and write locks cannot be shared).
  • Violating Hold and Wait: Require each process to request and be allocated all its required resources at once before execution begins. (Limitation: Extremely poor resource utilization; resources sit idle while waiting for long-lived tasks).
  • Violating No Preemption: If a process holding certain resources requests another resource that cannot be immediately allocated to it, the OS forcibly preempts all currently held resources, releasing them back to the system.
  • Violating Circular Wait (Global Lock Ordering): Assign a strict numerical ordering to all resource types ($R_1 < R_2 < \dots < R_n$). Enforce a global rule that threads must acquire resources in strictly ascending numerical order. If Thread A holds $R_5$, it cannot request $R_2$. This mathematically eliminates circular wait cycles.

3. Dijkstra's Banker's Algorithm (Deadlock Avoidance)

Proposed by Edsger Dijkstra, the Banker's Algorithm operates on the principle that the operating system acts like a banker managing cash liquidity with clients.

Mathematical Data Structures for Banker's Algorithm:
Let n be the number of processes and m be the number of resource types:
  • Available Vector [m]: A vector of length m indicating how many free instances of each resource type are currently available.
  • Max Matrix [n × m]: Defines the maximum demand of each process i for resource type j.
  • Allocation Matrix [n × m]: Defines the number of resources of each type currently allocated to process i.
  • Need Matrix [n × m]: Represents the remaining resource instances each process may still request:
    Need[i][j] = Max[i][j] - Allocation[i][j] 
/* Banker's Safety Algorithm Implementation */
bool is_system_safe(int n, int m, int available[], int max[][MAX_RES], int alloc[][MAX_RES]) {
    int work[MAX_RES];
    memcpy(work, available, m * sizeof(int));
    bool finish[MAX_PROC] = { false };

    int safe_sequence[MAX_PROC];
    int count = 0;

    while (count < n) {
        bool found = false;
        for (int i = 0; i < n; i++) {
            if (!finish[i]) {
                bool can_allocate = true;
                for (int j = 0; j < m; j++) {
                    if ((max[i][j] - alloc[i][j]) > work[j]) {
                        can_allocate = false;
                        break;
                    }
                }
                if (can_allocate) {
                    for (int j = 0; j < m; j++) {
                        work[j] += alloc[i][j];
                    }
                    safe_sequence[count++] = i;
                    finish[i] = true;
                    found = true;
                }
            }
        }
        if (!found) return false; /* Unsafe state! */
    }
    return true; /* System is safe */
}
