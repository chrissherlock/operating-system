01. Limited Direct Execution (LDE)

To virtualize the CPU efficiently without incurring catastrophic virtualization overhead, operating systems employ a technique known as Limited Direct Execution (LDE). As detailed in Operating Systems: Three Easy Pieces (OSTEP), "direct execution" means the OS simply runs the program directly on the bare CPU hardware. However, without limitations, a running program could execute infinite loops, access forbidden memory addresses, or hog the CPU indefinitely.

The Dual Role: Efficiency vs. Control

To reconcile bare-metal speed with absolute system protection, the kernel relies on two foundational hardware mechanisms:

  • Dual-Mode Operation: Modern CPUs support at least two execution modes—User Mode (Ring 3), where applications run with restricted privileges, and Kernel Mode (Ring 0 / Supervisor Mode), where the OS has unhindered access to physical memory, hardware registers, and privileged instructions.
  • Hardware Traps & System Calls: When a user-space application needs to perform a privileged operation (such as reading from disk or allocating memory), it executes a trap or syscall instruction. This hardware gate elevates privilege from Ring 3 to Ring 0 and jumps safely into a pre-registered kernel entry point.

Collaborative vs. Preemptive Scheduling

A major historical challenge in operating system design was regaining control of the CPU from a running program. In early collaborative multitasking systems (such as early Windows and Mac OS), the OS trusted programs to periodically yield the CPU back to the kernel via voluntary system calls. If a rogue application entered an infinite loop, the entire machine locked up.

Modern systems enforce preemptive multitasking via hardware timer interrupts. A timer chip triggers periodic interrupts at fixed intervals (e.g., every 10 milliseconds). When the timer expires, the hardware suspends the current program, saves its register state onto the kernel stack, and transfers control to the OS interrupt handler, allowing the scheduler to switch tasks.
