01. Limited Direct Execution & Process Tables

At the core of operating system design lies a fundamental architectural tension: how to achieve maximum execution performance while enforcing absolute system protection. Running programs directly on bare silicon yields peak execution speeds. However, without strict oversight, unconstrained user applications could monopolize the processor, corrupt memory bounds, or execute unauthorized I/O operations.

To resolve this challenge, operating systems implement Limited Direct Execution (LDE). By combining virtualization principles with structural kernel models, we can examine how hardware protection rings, interrupt vectors, process control blocks, and assembly-level context switches form the foundation of CPU virtualization.

1. The Mechanics of Limited Direct Execution

Direct execution means the CPU fetches, decodes, and executes user instructions natively without kernel intervention for every instruction. To maintain control, the OS must limit direct execution across two distinct phases: boot-time setup and runtime interposition.

  • Boot-Time Initialization: When the machine boots, the kernel initializes trap tables, configures interrupt descriptor tables (IDT), and sets up hardware memory protection registers, establishing safe entry points for hardware traps and timer interrupts.
  • Runtime Interposition: Once a user program is launched, the CPU switches to unprivileged User Mode. The program executes instructions directly until it either attempts a restricted operation or a hardware timer interrupt fires.

2. Dual-Mode Operation and Privilege Rings

Hardware protection relies on hierarchical privilege levels, commonly referred to as rings. On x86-64 architectures, Ring 0 represents Supervisor Mode (Kernel Mode), while Ring 3 represents User Mode.

  • Privileged Instructions: Operations such as disabling interrupts, modifying page table root pointers (CR3), altering power states, or issuing direct disk I/O commands can only be executed in Ring 0. Attempting these instructions in Ring 3 triggers an immediate hardware exception.
  • The Trap Gate: When a user program requires kernel services, such as reading a file or allocating memory, it executes a syscall or trap instruction. This hardware instruction acts as a controlled gateway, elevating privilege levels and transferring control to a verified kernel entry address.

3. Process Tables and Interrupt Vectors

Operating systems rely on precise kernel data structures to manage task execution. The central repository for process metadata is the Process Table, structured as an array or linked list of Process Control Blocks (PCBs) maintained in kernel memory. 

struct process_control_block {
    int pid;
    enum process_state state;
    struct cpu_registers saved_regs;
    uint64_t cr3_page_table_root;
    struct file_descriptor_table files;
};

When an interrupt or trap occurs, the CPU hardware consults the Interrupt Vector Table. The low-level execution sequence proceeds through distinct phases:

  1. Hardware stacks the program counter, program status word, and general registers.
  2. Hardware loads a new program counter from the interrupt vector into the CPU.
  3. An assembly-language procedure saves remaining general registers into the process table entry.
  4. The assembly-language procedure sets up a new stack for kernel execution.
  5. The C interrupt service routine runs to service the event, such as buffering input or acknowledging a timer tick.
  6. The scheduler evaluates runnable tasks to determine which process executes next.

4. Modeling Multiprogramming Efficiency

To evaluate CPU utilization under multiprogramming, operating systems analyze workloads probabilistically. If a process spends a fraction of its execution time waiting for I/O, the probability that multiple independent processes in memory are simultaneously waiting for I/O decreases exponentially with the degree of multiprogramming, allowing the system to mask latency and keep CPU cores saturated.
