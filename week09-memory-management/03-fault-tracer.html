Classifying Translation Failures

Tanenbaum Section 3.3.4 (Page 203): Differentiating Soft / Minor Misses, Hard Disk Faults, and Segmentation Violations.

Not All "Page Faults" Are Created Equal

Students often assume that whenever the CPU cannot translate a virtual address, the system must immediately read from a slow SSD or magnetic hard disk. In reality, translation failures fall into three distinct classes of varying severity and cost:

  1. Soft Miss (Minor Page Fault): The page is already resident in physical memory (DRAM), but it is not currently mapped into the process's page table or TLB. Examples include:
    • Shared libraries already loaded in memory by another process.
    • A page recently reclaimed to the OS free/standby list that hasn't been overwritten yet.
    Cost: ~10–20 machine instructions to link the PTE and update the TLB. Zero disk I/O.
  2. Hard Miss (Major Page Fault): The page is genuinely absent from physical RAM. The requested page contents reside on nonvolatile backing store (swap space, SSD, or an executable file on disk).
    Cost: Millions of CPU cycles. The OS must suspend the running process, schedule an asynchronous storage read, pick a victim frame to evict, and perform a context switch.
  3. Segmentation Violation (Invalid Access / SIGSEGV): The requested address does not belong to any valid virtual memory region defined in the process's address space layout (or violates access permissions, such as writing to a read-only text page).
    Outcome: The kernel delivers a SIGSEGV signal, typically terminating the process with a core dump.
TLB Miss → Hardware/OS walks Page Table
  └→ Present = 1 → Update TLB (Soft Miss, nanoseconds)
  └→ Present = 0, Valid Backing → Disk I/O (Hard Miss, milliseconds)
  └→ Unmapped Region → SIGSEGV (Invalid Address, crash)
