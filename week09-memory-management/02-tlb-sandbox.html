Speeding Up Paging: TLB & EMAT

Tanenbaum Section 3.3.3 (Fig. 3-12): The Translation Lookaside Buffer, hardware associativity, and Effective Memory Access Time.

The Paging Performance Dilemma

Virtual memory offers elegant protection and isolation, but introduces a major speed penalty. In basic paging, every memory reference requires at least two physical DRAM accesses:

  1. Look up the Page Table Entry (PTE) in physical DRAM to translate the virtual address to a physical frame.
  2. Access the actual operand, variable, or instruction at that physical address in DRAM.

Because reading DRAM takes tens of nanoseconds (100–200 CPU clock cycles), cutting program execution speed in half is unacceptable. The situation worsens with multi-level paging (such as 4-level x86-64 page tables), where a single memory access would require 4 table lookups plus the final data access—a 5x penalty!

The Solution: Translation Lookaside Buffer (TLB)

Computer systems leverage the principle of locality: programs tend to access a relatively small cluster of pages repeatedly over any given execution interval. Computer designers equip the MMU with a small, high-speed associative hardware cache called the Translation Lookaside Buffer (TLB).

The TLB holds between 64 and 1024 entries. When a virtual address arrives, the hardware queries all TLB entries simultaneously in parallel (associative search).

TLB Hit → PFN delivered in < 1 clock cycle (Bypasses Page Table DRAM walk completely)
TLB Miss → Hardware MMU or OS walks DRAM Page Table, loads entry into TLB, restarts instruction

Effective Memory Access Time (EMAT)

The overall memory speed is determined by the TLB hit ratio ($lpha$). If access to the TLB takes $ ext{time}_{tlb}$ (e.g., 1 ns) and DRAM takes $ ext{time}_{mem}$ (e.g., 100 ns):

EMAT = α × (time_tlb + time_mem) + (1 - α) × (time_tlb + 2 × time_mem)

With a 98% hit rate ($lpha = 0.98$), the average access time drops from 200 ns down to ~103 ns.
