What Is Virtual Memory?

Tanenbaum Section 3.1 & 3.2: The historical evolution from raw physical addressing to the modern virtual illusion.

The Problem Before Virtual Memory

In early computing (such as 1960s mainframes), programs referenced physical memory addresses directly. If a program was loaded into physical RAM starting at byte 0x1000, every internal jump and pointer had to be hardcoded relative to 0x1000.

This created two severe limitations:

  1. No Multiprogramming Protection: Program A could easily write a stray pointer to physical address 0x5000 and wipe out Program B or crash the operating system kernel.
  2. Memory Size Limit: If physical RAM was 32 MB, a program larger than 32 MB could never run because physical space was strictly bounded.

The Virtual Memory Revolution

Invented to solve these exact bottlenecks, Virtual Memory decouples the addresses used by a program (virtual addresses) from the actual storage locations in physical DRAM chips (physical addresses).

Virtual Address Space → (Translated on the fly by hardware MMU) → Physical DRAM Frames

Every process gets its own private, contiguous address space starting at 0x00000000. The operating system, assisted by CPU hardware (the Memory Management Unit or MMU), intercepts every memory reference and translates it transparently.
