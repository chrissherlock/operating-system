What Is Virtual Memory?

Tanenbaum Chapter 3 (Sec 3.1 & 3.2): The historical evolution from raw physical addressing, overlays, and swapping to modern virtual isolation.

1. The Historical Context: The Memory Constraint Problem

In the earliest decades of computing, physical memory (RAM) was extraordinarily expensive and strictly limited in capacity. If a mainframe computer had 64 KB of RAM, but a scientific simulation required 256 KB of instructions and data, the program simply could not run.

To bypass this, programmers had to manually restructure their software using a technique called overlays. The programmer manually divided their program into independent chunks. When Chunk A finished executing, it had to explicitly call system routines to load Chunk B from magnetic tape or disk into RAM over top of itself.

Overlays placed the entire burden of memory management on the human programmer, making large software development exceptionally tedious and error-prone.

2. The Birth of Virtual Memory & The Principle of Locality

In the early 1960s, computer scientists realized that at any given moment during a program's execution, only a small fraction of its code and data is actually being accessed. This observation is formalized as the Principle of Locality:

  • Temporal Locality: If a memory location is referenced once, it is likely to be referenced again soon (e.g., variables inside a tight loop).
  • Spatial Locality: If a memory location is referenced, nearby memory locations are likely to be accessed soon (e.g., sequential array traversal or sequential instruction execution).

Leveraging locality, Virtual Memory allows a program's virtual address space to be vastly larger than physical RAM. Only the active portions (working set) reside in physical DRAM; the rest remain safely stored on fast SSD swap partitions.

3. Address Spaces & The MMU

An address space is the set of all memory addresses that a process can generate.

  • Virtual Address Space: The abstract address range seen by the application code (e.g., 0x00000000 to 0x7FFFFFFF on a 32-bit process).
  • Physical Address Space: The actual hardware wiring of the DRAM chips plugged into the motherboard.

The hardware bridge between these two spaces is the Memory Management Unit (MMU)—a dedicated hardware circuit residing directly on the CPU chip. Every time the CPU issues a load or store instruction, the MMU intercepts the virtual address, consults translation tables, and outputs the translated physical address to the memory bus in under a nanosecond.
