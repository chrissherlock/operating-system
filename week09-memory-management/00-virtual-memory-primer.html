What Is Virtual Memory?

Tanenbaum Chapter 3 (Sec 3.1 & 3.2): The historical evolution from raw physical addressing, overlays, and swapping to modern virtual isolation.

1. The Historical Context: The Memory Constraint & Overlays

In early computing, physical memory (RAM) was strictly limited in capacity. If a mainframe computer had 64 KB of RAM, but a scientific simulation required 160 KB of code and data, the program simply could not fit into hardware.

To bypass this, programmers invented Overlays: manually partitioning a program into independent functional blocks that shared the exact same physical memory addresses. When Module A finished executing, it explicitly invoked disk-loading routines to overwrite itself in RAM with Module B.

2. The Birth of Virtual Memory & The Principle of Locality

Overlays placed the entire burden of memory management on the programmer. In the 1960s, operating systems automated this through Virtual Memory, enabled by the Principle of Locality:

  • Temporal Locality: If a memory location is referenced once, it is likely to be referenced again soon (e.g., loop counters).
  • Spatial Locality: If a memory location is referenced, nearby locations are likely to be accessed soon (e.g., sequential array iteration).

Because of locality, only active working sets need to sit in DRAM; inactive pages reside safely on SSD swap storage.

3. Address Spaces & The MMU

The Memory Management Unit (MMU) is a hardware circuit on the CPU that translates virtual addresses to physical RAM addresses transparently in under a nanosecond, giving every process its own isolated private address space.
