Tanenbaum Chapter 3: Bookkeeping via Bitmaps, Linked Lists of Free/Allocated Segments, First/Best/Worst Fit, and Binary Buddy Systems.

Tanenbaum's Bookkeeping Methods: Bitmaps vs. Linked Lists

According to Tanenbaum, when managing memory with variable-sized allocation, an operating system can track free and used space using two primary mechanisms:

1. Memory Management with Bitmaps

Memory is divided into allocation units (e.g., 4 KB blocks). Each unit corresponds to a bit in a bitmap: 0 if free, 1 if allocated. Tradeoff: Simple to maintain and fixed in size, but searching for a contiguous run of k free units requires scanning sequential bits slowly.

2. Memory Management with Linked Lists

The operating system maintains a linked list of allocated and free memory segments. Each entry specifies whether the region is a Hole (H) or a Process (P), its starting address, and its length.

Classical Contiguous Allocation Strategies (First Fit, Best Fit, Worst Fit, Next Fit)

When a process requests memory against a linked list of holes, the operating system uses placement algorithms to decide which hole to assign:

  • First Fit: Scan the list from the beginning and choose the first hole that is big enough. Fast, but creates many small splinters at the front.
  • Best Fit: Search the entire list and choose the hole closest in size to the request. Minimizes waste per allocation, but leaves behind tiny, unusable slivers and requires exhaustive searching.
  • Worst Fit: Allocate from the largest available hole so the leftover fragment remains useful. In practice, it performs poorly and rapidly exhausts large blocks.
  • Next Fit: Like First Fit, but starts scanning from where the last search left off rather than the beginning. Spreads allocation evenly.
What is a PFN (Page Frame Number)?
Physical DRAM is partitioned by hardware into fixed-sized slots called page frames (commonly 4096 bytes or 212). The PFN is simply the sequential integer index of that frame:
PFN =
Physical Address 4096
= Physical Address >> 12
Physical address 0x0000 is PFN 0, 0x1000 is PFN 1, 0x2000 is PFN 2, and so on. The buddy system performs all pairing directly on this integer index.
