02. Directory Systems & Hierarchies

Tanenbaum Chapter 4.2: Comprehensive Reference on Directory Structures, Path Resolution, and Directory System Calls.

4.2.1 & 4.2.2 Directory Structures: Single-Level, Two-Level & Hierarchical

To keep track of thousands or millions of individual files stored on persistent media, operating systems organize files using directories (folders). A directory acts as a symbol table, translating file names into their corresponding metadata or disk block addresses.

1. Single-Level Directory Systems

The earliest and simplest directory architecture consists of a single directory containing all files for all users. Every file must possess a completely unique name, leading to frequent naming collisions in multi-user environments.

2. Two-Level Directory Systems

Maintains a master directory containing one entry for every user, pointing to separate private user directories. Different users can create files with identical names, but internal subdirectories remain unsupported.

3. Hierarchical (Tree-Structured) Directory Systems

Modern operating systems implement hierarchical directory structures configured as arbitrary trees starting from a designated root directory (/ in UNIX or C:\ in Windows).

4.2.3 Path Names

To locate a file within a hierarchy, applications specify paths using two primary formats:

  • Absolute Paths: Specify the exact traversal route starting from the root directory (e.g., /home/student/cosc240/lab10.c).
  • Relative Paths: Specify a route starting from the calling context's current working directory (CWD), utilizing special directory entries such as . (current directory) and .. (parent directory).

4.2.4 Directory Operations & System Calls

Operating systems provide a specialized suite of system calls to manage directories and link namespaces together:

  1. Create: Creates a new, empty directory (such as mkdir). Initially, it contains only two entries: . (referencing itself) and .. (referencing its parent).
  2. Delete: Removes a directory. Most operating systems require the directory to be completely empty (containing only . and ..) before deletion is permitted.
  3. Opendir: Opens a directory for reading, returning a directory stream pointer or descriptor.
  4. Readdir: Reads the next entry from an open directory stream, returning file names and i-node numbers. Historically, applications read raw directory bytes directly, but modern systems enforce readdir to abstract internal directory block layouts and prevent direct corruption of symbol tables.
  5. Closedir: Releases directory stream resources when directory traversal concludes.
  6. Rename: Changes a file or directory name within the namespace tree without duplicating underlying data blocks.
  7. Link: Creates a new hard link—an additional directory entry pointing to an existing file's i-node. This allows a single file to exist under multiple names or in different directories simultaneously.
  8. Unlink: Removes a directory entry. If the entry being unlinked is the final hard link pointing to an i-node (and no execution contexts have it open), the i-node and its associated data blocks are deallocated.
