02. Directory Systems & Hierarchies

Tanenbaum Chapter 4.2: Comprehensive Reference on Single-Level, Two-Level, and Hierarchical Directory Structures.

4.2.1 Single-Level & Hierarchical Directories

To keep track of thousands or millions of individual files stored on persistent media, operating systems organize files using directories (also referred to as folders in various environments). A directory is itself a system-managed file that acts as a symbol table, translating file names into their corresponding metadata or disk block addresses. Across the evolution of operating systems, three primary directory organization models have emerged.

1. Single-Level Directory Systems

The earliest and simplest directory architecture consists of a single directory containing all files for all users.

  • Characteristics: Every file within the system must possess a completely unique name. Because there is only one shared namespace, two different users cannot create files with identical names (such as notes.txt or main.c).
  • Advantages: Implementation is straightforward; file lookup requires scanning a single flat list, and system calls are computationally minimal.
  • Limitations: In multi-user computing environments, name collisions become frequent and unmanageable. Isolating projects or maintaining user privacy is impossible without complex naming prefixes.
2. Two-Level Directory Systems

To resolve name collisions in multi-user systems, operating systems introduced a two-level directory hierarchy.

  • Characteristics: The system maintains a master directory containing one entry for every user. Each user entry points to a separate, private user directory containing that specific user's files.
  • Advantages: Different users can now create files with identical names (e.g., User A and User B can both maintain a file named budget.csv) because names are scoped within individual user directories.
  • Limitations: While isolation between users is achieved, individual users cannot group or organize their own files into subdirectories. As a user accumulates hundreds of files, a flat single-level list within their private directory becomes difficult to manage.
3. Hierarchical (Tree-Structured) Directory Systems

Modern operating systems (including UNIX, Linux, macOS, and Windows) implement hierarchical directory structures configured as arbitrary trees.

  • Characteristics: Users can create arbitrary subdirectories within their own directories, nesting folders to any logical depth. The file system begins at a designated root directory (denoted by / in UNIX or drive letters like C:\ in Windows).
  • Path Resolution: To locate a file within a hierarchy, applications specify paths using two primary formats:
    • Absolute Paths: Specify the exact traversal route starting from the root directory (e.g., /home/student/cosc240/lab10.c).
    • Relative Paths: Specify a route starting from the calling application's current working directory (CWD), utilizing special directory entries such as . (referencing the current directory) and .. (referencing the parent directory).
