01. Files & Naming Abstractions

Tanenbaum Chapter 4.1: Comprehensive Reference on File Naming, Structures, Types, Access, Attributes, and POSIX System Calls.

4.1.1 File Naming

The most important characteristic of any abstraction mechanism is the way objects are named[cite: 4]. When a process creates a file, it assigns a name[cite: 4]. Upon process termination, the file persists and can be accessed by other processes using that name[cite: 4].

  • Character Sets & Length: Current operating systems allow strings of letters, digits, and special characters (e.g., `2`, `urgent!`, `Fig.2-14`)[cite: 4]. While older systems like MS-DOS restricted names to 8+3 characters, modern systems support file names up to 255 characters or more[cite: 4].
  • Case Sensitivity: UNIX systems distinguish between upper- and lowercase letters (treating `maria`, `Maria`, and `MARIA` as three distinct files), whereas MS-DOS and older Windows architectures treat them as identical[cite: 4]. Modern Windows versions inherit backward compatibility with FAT-16/FAT-32 file systems while providing advanced file management.

4.1.2 File Structure

File organization models vary across operating systems and application requirements[cite: 4]:

  1. Unsequence of Bytes: Used by UNIX and Windows. The file is simply a stream of bytes; the operating system does not interpret or structure the contents[cite: 4]. Any internal formatting is up to applications.
  2. Record Sequences: Modeled as a sequence of fixed-length records, each with internal structure (historically derived from 80-column punched cards or 132-character printer lines)[cite: 4].
  3. Key-Indexed Trees: Consists of records of varying lengths, each containing a key field. The file is sorted on the key, allowing applications to retrieve records by key rather than relative position (common in large mainframe commercial data processing)[cite: 4].

4.1.3 File Types

Operating systems recognize and support multiple file classifications[cite: 4]:

  • Regular Files: User-information containers divided into ASCII files (lines terminated by line feed or carriage return, easily edited and piped) and binary files (executable programs with magic numbers and headers, libraries, or archives)[cite: 4].
  • Directories: System-managed files that maintain the hierarchical structure of the file system[cite: 4].
  • Character Special Files: Used to model serial I/O devices (terminals, printers, networks)[cite: 4].
  • Block Special Files: Used to model disk storage drives[cite: 4].

4.1.4 File Access

Early operating systems provided only sequential access, where a process had to read all bytes or records in order from the beginning[cite: 4]. With the advent of disk storage, random-access files emerged, enabling bytes or records to be accessed out of order or by key[cite: 4]. Modern systems support explicit seeking via system calls like `lseek` to reposition the file offset pointer[cite: 4].

4.1.5 File Attributes (Metadata)

Operating systems associate extra administrative metadata with every file[cite: 4]. While attributes differ across platforms, standard metadata includes[cite: 4]:

Attribute Meaning / Description
ProtectionControls who may access the file and with what permissions (Read/Write/Execute)[cite: 4].
Owner / CreatorIdentifies the user who created or currently owns the file (UID/GID)[cite: 4].
FlagsHidden, system, read-only, archive (tracks whether file needs backup), temporary, and lock flags[cite: 4].
TimestampsExact creation time, time of last access, and time of last attribute/data modification[cite: 4].
File SizeCurrent byte count and maximum permissible growth limit[cite: 4].

4.1.6 File Operations & System Calls

Common system calls provided by operating systems for file management include[cite: 4]:

  1. create: Initializes a new empty file with specified attributes[cite: 4].
  2. delete: Removes a file and reclaims its disk space[cite: 4].
  3. open: Fetches attributes and disk addresses into main memory for rapid access[cite: 4].
  4. close: Flushes final cached blocks and frees internal table space[cite: 4].
  5. read: Retrieves data from a file into a user-provided buffer[cite: 4].
  6. write: Outputs data to a file at the current offset or end[cite: 4].
  7. append: Restricted write mode adding data exclusively to the end of a file[cite: 4].
  8. lseek: Repositions the file offset pointer for random access[cite: 4].
  9. get/set attributes: Reads or modifies file metadata (e.g., protection modes, timestamps)[cite: 4].
  10. rename: Changes a file's name within the directory structure[cite: 4].

4.1.7 Example: POSIX File-Copy Program

Below is a standard POSIX C implementation illustrating file descriptor handling, error checking, and block-by-block streaming using open, creat, read, write, and close[cite: 4]: 

#include <sys/types.h>
#include <fcntl.h>
#include <stdlib.h>
#include <unistd.h>

#define BUF_SIZE 4096
#define OUTPUT_MODE 0700

int main(int argc, char *argv[]) {
    int in_fd, out_fd, rd_count, wt_count;
    char buffer[BUF_SIZE];

    if (argc != 3) exit(1); // Syntax error

    in_fd = open(argv[1], O_RDONLY);
    if (in_fd < 0) exit(2); // Source open failed

    out_fd = creat(argv[2], OUTPUT_MODE);
    if (out_fd < 0) exit(3); // Destination creation failed

    while (1) {
        rd_count = read(in_fd, buffer, BUF_SIZE);
        if (rd_count < 0) exit(4); // Read error
        if (rd_count == 0) break; // EOF reached

        wt_count = write(out_fd, buffer, rd_count);
        if (wt_count <= 0) exit(5); // Write error
    }

    close(in_fd);
    close(out_fd);
    exit(0);
}
